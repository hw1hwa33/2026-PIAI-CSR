# 02_UIUX_CORE

## 목적

화면을 예쁘게 만들기 전에
사용자가 무엇을 보고 무엇을 해야 하는지 명확하게 만든다.

---

## 1. Information Hierarchy

모든 화면은 다음 위계를 가져야 한다.

PRIMARY
- 가장 중요한 메시지
- 핵심 결론
- 현재 상태

SECONDARY
- 근거
- 비교
- 핵심 수치

TERTIARY
- 세부 설명
- 참고 정보

모든 요소를 같은 크기와 강조도로 만들지 않는다.

---

## 2. First-Screen Rule

사용자는 첫 화면 또는 첫 5초 안에 다음을 알아야 한다.

- 이 페이지가 무엇인지
- 가장 중요한 정보가 무엇인지
- 무엇을 조작할 수 있는지
- 다음에 무엇을 해야 하는지

---

## 3. Progressive Disclosure

모든 정보를 처음부터 노출하지 않는다.

기본:
- 전체 구조
- 핵심 요약
- 주요 수치

선택 후:
- 상세 설명
- 비교
- 근거
- 세부 데이터

---

## 4. Affordance

클릭 가능한 요소는 클릭 가능해 보여야 한다.

버튼처럼 보이는 요소는 실제 버튼이어야 한다.

텍스트 링크, 토글, 탭, 필터는 일관된 시각 규칙을 사용한다.

---

## 5. Current State Visibility

사용자는 항상 다음을 알 수 있어야 한다.

- 현재 선택한 항목
- 현재 필터
- 현재 화면 상태
- 무엇이 변경되었는지

Selected / Active / Disabled 상태를 명확히 구분한다.

---

## 6. Feedback

모든 행동에는 피드백이 있어야 한다.

Hover
→ 시각 피드백

Click
→ 선택 피드백

Loading
→ 진행 피드백

Error
→ 문제 원인 및 다음 행동

Success
→ 완료 상태

---

## 7. Navigation

내비게이션은 사용자 목적을 방해하지 않아야 한다.

연속 단계가 존재하면:
- 이전
- 다음

을 제공할 수 있다.

복잡한 분석 화면에서는 현재 위치를 잃지 않게 한다.

---

## 8. Modal

Modal은 제한적으로 사용한다.

적합:
- 중요한 확인
- 집중적인 단기 작업
- 사용자의 즉각적인 결정 필요

부적합:
- 단순 상세 정보
- 작은 설명
- 반복적으로 확인해야 하는 정보

대안:
- Drawer
- Inline Panel
- Expand
- Side Panel

---

## 9. Empty / Error / Loading

정상 상태만 디자인하지 않는다.

최소 검토:
- Loading
- Empty
- Error
- Disabled
- Success

빈 화면은 의미 있는 Empty State로 교체한다.

---

## 10. Usability Gate

다음 질문 중 하나라도 즉시 답하기 어렵다면 수정한다.

- 어디를 봐야 하는가?
- 무엇을 할 수 있는가?
- 지금 무엇이 선택되었는가?
- 다음 행동은 무엇인가?
